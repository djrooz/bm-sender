# BM Sender — еженедельные отчёты родителям

Автоматизация подготовки еженедельных отчётов родителям участников трека
BizMission по итогам кураторских Zoom-встреч (саммари из Fireflies) и
публикации черновиков в Telegram-чат кураторов после подтверждения
пользователя.

**Ничего не отправляется в Telegram без явного "ок" от пользователя в чате.**

## Настройка (один раз)

1. Скопировать `.env.example` → `.env`, заполнить:
   - `FIREFLIES_API_KEY` — Fireflies → Settings → Developer Settings.
   - `TELEGRAM_BOT_TOKEN` — токен бота от @BotFather.
   - `TELEGRAM_CHAT_ID` — chat_id группы кураторов. Чтобы узнать: добавить
     бота в группу, написать туда любое сообщение, затем
     `python telegram_client.py whoami`.
2. `pip install -r requirements.txt`.

## Источник списка участников

Гугл-таблица `GOOGLE_SHEET_ID` (без заголовков, 3 колонки: Участник (Фамилия
Имя) | Родитель(и) | Мессенджер). Мессенджер — только для шапки сообщения
куратору; фактическая доставка всегда через один и тот же Telegram-чат
кураторов, дальше куратор сам пересылает родителю в нужный мессенджер.

У Claude Code уже есть доступ к Google Drive MCP — таблицу читает сам агент
(`read_file_content` по `GOOGLE_SHEET_ID`), отдельных Google-credentials не
нужно. Полученный markdown прогнать через `roster.parse_roster_markdown` и
закэшировать `roster.save_roster(...)`, чтобы дальше пользоваться
`roster.load_roster()`.

## Еженедельный процесс — ручной запуск (по команде пользователя, например
«сделай отчёты за эту неделю»)

1. Обновить `roster.json` (см. выше) — актуальный список участников
   (`roster.load_roster()`, читает CSV-экспорт таблицы напрямую).
2. Определить период: по умолчанию последние 7 дней (сегодня минус 7 дней —
   сегодня), либо период, который явно укажет пользователь.
3. Для каждого участника:
   `fireflies_client.find_meetings_for(participant.fio, date_from, date_to)`.
   - Если встреч нет или у всех найденных встреч пустое саммари — не
     выдумывать отчёт, отметить участника отдельно в сообщении пользователю
     ("по Х встреч на этой неделе не было / саммари ещё не готово").
   - Если встреч несколько — использовать все, синтезировать один отчёт.
4. Написать черновик отчёта для каждого участника со встречами, строго в
   стиле образца (см. ниже). Основа текста — `overview`/`bullet_gist` из
   Fireflies, не выдумывать детали, которых нет в саммари.
5. Показать пользователю в чате все черновики целиком (участник → текст),
   попросить подтверждение/правки.
6. После подтверждения — для каждого одобренного отчёта:
   `telegram_client.send_message(header + "\n\n" + report_text)`, где
   `header = f"{participant.fio} — {participant.parents} — {participant.messenger}"`.

## Автоматический еженедельный запуск (пятница 11:00 МСК, cron)

Тот же процесс, что и ручной (шаги 1–4 выше), но **без шага подтверждения** —
пользователь явно попросил публиковать сразу в группу кураторов без
предварительного показа черновиков. Отличия:

- Период всегда — последние 7 дней от момента запуска.
- Участников без встреч/без готового саммари за неделю — просто пропустить
  молча (без отчёта и без отдельного уведомления), не отправлять пустые или
  придуманные отчёты.
- Для каждого участника с реальным содержанием сразу вызвать
  `telegram_client.send_message(header + "\n\n" + report_text)`.
- Доступ к таблице — публичный CSV-экспорт (`roster.py`), доступ к Fireflies
  и Telegram — через `.env`, интерактивных MCP-инструментов в cron-агенте
  может не быть, поэтому весь пайплайн должен быть самодостаточен (см.
  `roster.py`, `fireflies_client.py`, `telegram_client.py`).

## Стиль отчёта

Формат-обёртка (не менять):

```
Стас, Елена, здравствуйте!

➡️ Отчёт по треку Евы за период 15.06–21.06

🔸 Синхронизация с куратором

<текст по правилам ниже>

🔸 Дальнейшие шаги

<текст по правилам ниже>
```

- Обращение — по именам из колонки «Родитель(и)» (например «Стас, Елена,
  здравствуйте!» для «Стас и Елена»; «Александр, здравствуйте!» для
  одного имени).
- Заголовок отчёта — по имени участника (обычно только имя, не фамилия),
  период — `ДД.ММ–ДД.ММ` (даты периода прогона).
- Эмодзи-разделители 🔸 ровно как в образце (не изобретать новые).

### Главный принцип

Отчёт — не протокол встречи и не конспект занятия. Его задача — за 1–2
минуты дать родителю ответ на четыре вопроса: что произошло за неделю? что
стало результатом? почему это важно для развития участника? что дальше?
Если предложение не отвечает хотя бы на один из этих вопросов — его не
должно быть в тексте.

Каждый абзац строится по схеме: **событие → результат → зачем это важно →
следующий шаг**. Пример:
- ❌ «На встрече обсудили GROW, SMART, активное слушание и кодекс ICF.»
- ✅ «Продолжили обучение основам коучинга. На этой неделе София разобрала
  базовую структуру работы с запросом клиента и теперь готовится провести
  первую тренировочную сессию.»

### Чего никогда не делать

1. **Не пересказывать встречу** — не перечислять всё, о чём говорили
   («поговорили про Париж, потом про Wi-Fi, потом про друзей...»).
2. **Не писать конспект обучения** — не перечислять пройденные модели/темы
   (GROW, SMART и т.п.), только факт и стадию: «продолжили обучение
   коучинговым инструментам», «освоили базовую структуру сессии».
3. **Не писать всё, что знаете** — если факт не влияет на развитие, не
   меняет план и не является результатом, его не нужно писать.
4. **Не повторять то, что родители и так знают** — если родители сами были
   на встрече (семейный созвон), не пересказывать её. Максимум одна фраза:
   «На семейной встрече синхронизировали организационные вопросы поездки».
5. **Не писать бытовые подробности** — плохой Wi-Fi, смена отеля, что
   участник ел/фотографировал/по чему скучает — это не относится к
   развитию, убирать полностью.
6. **Не переносить личные разговоры в отчёт** — то, что участник рассказал
   куратору (переживания, отношения в семье, оценки других людей), не
   становится автоматически можно писать родителям, даже если прозвучало на
   встрече. Это нарушение доверия.
7. **Не делать выводов, которых не было** — никаких похвал/характеристик
   («самостоятельное мышление», «отлично ориентируется»), если это нельзя
   объективно увидеть по факту встречи.
8. **Не приписывать значение случайным фразам** — если на встрече мельком
   упомянули инструмент/тему, это не повод писать вывод о владении им.
9. **Не подменять факты интерпретациями** — «получил кейс» ≠ «разобрал
   кейс»; «куратор рассказал о кейсе» ≠ «участник уже работает над
   стратегией». Точно разделять, что уже произошло, а что только предстоит.
10. **Не писать обещания, которых не было** — внутренние рабочие
    договорённости команды (например, «ежедневный контроль наставника»,
    «знакомство с …») не переносить в отчёт как согласованный факт, если
    это не прямое обязательство перед участником/родителем. Личный пример
    куратора («у кого-то был перевод на бюджет», «спортивные достижения
    иногда дают скидку») — это не текущий план участника, не включать.
11. **Не выносить второстепенную реплику в главный тезис абзаца** — если на
    встрече мельком упомянули инструмент (Miro) или дали один комментарий
    (не всем клиентам подходит визуализация), это не может стать смысловым
    центром абзаца. Главный результат недели — то, что реально сдвинулось
    (получен кейс, освоена структура сессии), а не случайное упоминание.
12. **Не смешивать репетицию на встрече с реальным следующим событием** —
    если участник тренировался отвечать на вопросы собеседования прямо на
    встрече с куратором, это не то же самое, что «собеседование с
    принимающей стороной» — это разные события, разносить по разным
    предложениям.
13. **Не переносить бытовой юмор/сленг из встречи** — если в разговоре
    прозвучало шутливое «подопытный кролик» про человека, для практики, в
    отчёте — нейтрально: «приглашённый участник».
14. **Национальность, личные антипатии, оценочные суждения об отдельных
    людях/группах — исключать полностью**, даже если это был просто
    случайный комментарий в разговоре, а не что-то серьёзное.
15. **Не повторять то, что явно похоже на ошибку распознавания** — если
    цифра в саммари выглядит физически бессмысленной (например, «потеряли
    300% пользователей»), не переносить её в отчёт как факт — просто не
    называть точную цифру.
16. **Не смешивать организационные задачи семьи/поездки с шагами по
    треку участника** — в «Дальнейшие шаги» идёт только то, что двигает
    развитие/обучение участника; логистика поездки (билеты, отели, даты)
    там не нужна, даже если формально обсуждалась на той же встрече.

### Что нужно писать

- Через результат: не «обсудили…», а «сформировали…», «определили…»,
  «подготовили…», «начали…», «завершили…», «приступили…».
- С динамикой: не «поговорили про…», а «переходим к…», «следующим этапом
  станет…», «основной фокус сейчас смещается на…».
- С объяснением зачем: «Продолжили работу над резюме, чтобы подготовить
  материалы для поиска первой профессиональной практики» — а не просто
  «работали над резюме».
- С акцентом на действиях участника, а не куратора: «участник подготовил…,
  попробовал…, сформулировал…» — а не «куратор рассказал…».
- Про путешествия — только если это влияет на процесс, и одной фразой:
  «Сейчас Илья в поездках, поэтому синхронизации подстраиваются под его
  график» — без деталей, куда/что/зачем.

### Язык

Спокойный, взрослый, профессиональный, уверенный, без лишней
эмоциональности и без воды. Избегать «поговорили / обсудили / рассказали /
объяснили» — предпочитать «сформировали / определили / продолжили /
начали / подготовили / переходим / следующим этапом станет».

### Образец полного отчёта (эталон стиля, одобрен пользователем)

```
Александр, здравствуйте!

➡️ Отчёт по треку Ильи за период 17.07–24.07

🔸 Синхронизация с куратором

На этой неделе провели с Ильёй индивидуальную синхронизацию. Поскольку
после поездки он ещё восстанавливался, встречу сделали более короткой, но
уже определили следующий практический фокус работы.

Илья получил новый бизнес-кейс, основанный на реальном задании для
assessment в Deloitte. В рамках кейса ему предстоит разработать стратегию
возвращения молодой аудитории стримингового сервиса с учётом заданного
бюджета и ограниченного срока реализации.

Задача направлена на развитие аналитического и стратегического мышления:
Илье важно будет не только предложить идеи, но и обосновать их, определить
приоритеты и собрать решение в понятную структуру.

Также договорились после восстановления отдельно синхронизироваться по его
актуальным интересам и запросам, чтобы определить следующие менторские
знакомства и направления обучения.

Отдельно на семейной встрече сверили основные организационные вопросы
предстоящей поездки в США и ближайшие задачи по подготовке.

🔸 Дальнейшие шаги

На следующем этапе Илья самостоятельно подготовит решение бизнес-кейса.
После этого вместе разберём его подход, сравним с примером решения и
обсудим обратную связь, полученную по исходному кейсу.

Параллельно определим приоритетные темы для следующих менторских встреч,
чтобы они были связаны с текущими интересами и задачами Ильи.
```

Почему это хорошо: нет пересказа бытового разговора (болезнь — одной
фразой, только чтобы объяснить формат встречи), нет лишней логистики
поездки (семейная встреча — одна строка, без деталей класса перелёта/
отеля, которые родитель и так знает), нет преждевременной похвалы (не
«проявил вовлечённость», а нейтрально «получил кейс», «предстоит
разработать»), чётко разделены факт (кейс получен) и будущее (кейс будет
решён, потом разобран вместе).

### Чек-лист перед отправкой

- Фактическая точность: всё соответствует саммари встречи; нет придуманных
  выводов, преувеличений, обещаний, которых не было.
- Полезность: каждое предложение отвечает на «зачем родителю это знать?»;
  нет пересказа встречи, конспекта обучения, бытовых деталей.
- Конфиденциальность: нет личных признаний участника, семейных деталей,
  внутренних рабочих гипотез команды.
- Стиль: есть ощущение движения и развития, есть следующий шаг; нет воды и
  фраз ради объёма.
