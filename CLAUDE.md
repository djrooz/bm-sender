# BM Sender — еженедельные отчёты родителям

Автоматизация подготовки еженедельных отчётов родителям участников трека
BizMission по итогам кураторских Zoom-встреч (саммари из Fireflies) и
публикации черновиков в Telegram-чат кураторов после подтверждения
пользователя.

**Ничего не отправляется в Telegram без явного "ок" от пользователя в чате.**

## Настройка (один раз)

1. Скопировать `.env.example` → `.env`, заполнить:
   - `FIREFLIES_API_KEY` — Fireflies → Settings → Developer Settings.
   - `TELEGRAM_BOT_TOKEN` — токен бота от @BotFather.
   - `TELEGRAM_CHAT_ID` — chat_id группы кураторов. Чтобы узнать: добавить
     бота в группу, написать туда любое сообщение, затем
     `python telegram_client.py whoami`.
2. `pip install -r requirements.txt`.

## Источник списка участников

Гугл-таблица `GOOGLE_SHEET_ID` (без заголовков, 3 колонки: Участник (Фамилия
Имя) | Родитель(и) | Мессенджер). Мессенджер — только для шапки сообщения
куратору; фактическая доставка всегда через один и тот же Telegram-чат
кураторов, дальше куратор сам пересылает родителю в нужный мессенджер.

У Claude Code уже есть доступ к Google Drive MCP — таблицу читает сам агент
(`read_file_content` по `GOOGLE_SHEET_ID`), отдельных Google-credentials не
нужно. Полученный markdown прогнать через `roster.parse_roster_markdown` и
закэшировать `roster.save_roster(...)`, чтобы дальше пользоваться
`roster.load_roster()`.

## Еженедельный процесс — ручной запуск (по команде пользователя, например
«сделай отчёты за эту неделю»)

1. Обновить `roster.json` (см. выше) — актуальный список участников
   (`roster.load_roster()`, читает CSV-экспорт таблицы напрямую).
2. Определить период: по умолчанию последние 7 дней (сегодня минус 7 дней —
   сегодня), либо период, который явно укажет пользователь.
3. Для каждого участника:
   `fireflies_client.find_meetings_for(participant.fio, date_from, date_to)`.
   - Если встреч нет или у всех найденных встреч пустое саммари — не
     выдумывать отчёт, отметить участника отдельно в сообщении пользователю
     ("по Х встреч на этой неделе не было / саммари ещё не готово").
   - Если встреч несколько — использовать все, синтезировать один отчёт.
3a. Для каждой найденной встречи дополнительно вызвать
    `fireflies_client.get_full_transcript(meeting.id)` и прочитать полный
    текст (реплики спикеров), а не только `summary`. Summary Fireflies —
    это уже сжатая AI-выжимка, в ней теряются нюансы и иногда встречаются
    искажения (обрывки цифр, неверные акценты). Полный транскрипт — основной
    источник фактов для отчёта; `summary` можно использовать только для
    быстрой ориентации, что вообще было на встрече.
4. Написать черновик отчёта для каждого участника со встречами, строго в
   стиле образца (см. ниже). Основа текста — полный транскрипт встречи
   (см. 3a), не выдумывать детали, которых там нет.
5. Показать пользователю в чате все черновики целиком (участник → текст),
   попросить подтверждение/правки.
6. После подтверждения — для каждого одобренного отчёта:
   `telegram_client.send_message(header + "\n\n" + report_text)`, где
   `header = f"{participant.fio} — {participant.parents} — {participant.messenger}"`.

## Автоматический еженедельный запуск (пятница 11:00 МСК, cron)

Тот же процесс, что и ручной (шаги 1–4 выше), но **без шага подтверждения** —
пользователь явно попросил публиковать сразу в группу кураторов без
предварительного показа черновиков. Отличия:

- Период всегда — последние 7 дней от момента запуска.
- Участников без встреч/без готового саммари за неделю — просто пропустить
  молча (без отчёта и без отдельного уведомления), не отправлять пустые или
  придуманные отчёты.
- Для каждого участника с реальным содержанием сразу вызвать
  `telegram_client.send_message(header + "\n\n" + report_text)`.
- Доступ к таблице — публичный CSV-экспорт (`roster.py`), доступ к Fireflies
  и Telegram — через `.env`, интерактивных MCP-инструментов в cron-агенте
  может не быть, поэтому весь пайплайн должен быть самодостаточен (см.
  `roster.py`, `fireflies_client.py`, `telegram_client.py`).

## Стиль отчёта

Формат-обёртка (не менять):

```
Стас, Елена, здравствуйте!

➡️ Отчёт по треку Евы за период 15.06–21.06

🔸 Синхронизация с куратором

<текст по правилам ниже>

🔸 Дальнейшие шаги

<текст по правилам ниже>
```

- Обращение — по именам из колонки «Родитель(и)» (например «Стас, Елена,
  здравствуйте!» для «Стас и Елена»; «Александр, здравствуйте!» для
  одного имени).
- Заголовок отчёта — по имени участника (обычно только имя, не фамилия),
  период — `ДД.ММ–ДД.ММ` (даты периода прогона). Имя участника — то,
  которое принято в текущей коммуникации с этой семьёй (см. п.19), не
  менять на официальную форму без причины.
- Эмодзи-разделители 🔸 ровно как в образце (не изобретать новые).
- Писать от первого лица множественного числа («мы») — сообщение и так
  отправляется от лица куратора/команды. Не «куратор свяжется с Кириллом»,
  а «мы свяжемся с Кириллом»; не «вместе с куратором разберём», а просто
  «вместе разберём». Слово «куратор» в третьем лице по отношению к себе не
  использовать.

### 1. Задача касания

Касание — это не расшифровка встречи, не отчёт о каждом обсуждённом
вопросе и не конспект занятия. За 1–2 минуты оно должно дать родителю
ответы на четыре вопроса: что содержательно произошло за неделю? какой
результат получен? почему этот результат важен для развития участника?
что будет происходить дальше?

Логика каждого смыслового блока: **что произошло → что это дало → зачем
это важно → какой следующий шаг**.

### 2. Общая структура

- Приветствие — имя(ена) родителя в принятом формате.
- Заголовок — `➡️ Отчёт по треку [имя] за период [даты]`.
- `🔸 Синхронизация с куратором` — значимые действия участника, результаты
  встречи, изменения в процессе, сформированные решения, начатые/
  завершённые этапы, навыки в развитии, связь с общей целью программы.
- `🔸 Дальнейшие шаги` — конкретное следующее действие участника, следующий
  этап работы, ожидаемый результат, что предстоит согласовать.

### 3. Главный фильтр

Перед включением любой фразы — вопрос «зачем родителю это знать?».
Оставлять только то, что показывает движение участника, объясняет
результат, помогает понять логику работы, влияет на дальнейшие шаги или
требует внимания/участия родителя. Просто прозвучавшее на встрече, но не
влияющее на процесс — не включать.

### 4. Не пересказывать встречу

❌ «Поговорили о поездке, обсудили отель, Wi-Fi, планы на Париж,
фотографии и предстоящий кемп.»
✅ «Провели поддерживающую синхронизацию. Сейчас у Евы насыщенный график
поездок и тренировочных сборов, поэтому встречи временно подстраиваем под
её расписание.»
Забираем из разговора смысл, а не все детали.

### 5. Не включать то, что родители уже знают

Результаты экзамена, которые родители уже получили; маршрут семейной
поездки; выбранные билеты/отели; расписание, которое родители сами
составляли; содержание встречи, на которой родители присутствовали;
семейные организационные договорённости, известные адресату.

❌ «Арсений пересдал математику и получил 94 балла.» (родители уже знают
результат — для них это не новость)
✅ «На этой неделе основной фокус сместился на подготовку Арсения к
возможной стажировке.»

❌ «На семейной встрече обсудили премиум-эконом, Airbnb и перелёт из
Дубая.»
✅ «На семейной встрече синхронизировали основные организационные вопросы
поездки в США.»

### 6. Не включать бытовые подробности

Интернет, еда, покупки, фотографии, бытовые сложности поездки, смена
отеля, потерянные деньги, игрушки, одежда, случайные истории, шутки,
повседневные планы. Такие детали поддерживают живой разговор участника с
куратором, но результатом программы не являются.

### 7. Конфиденциальность общения с участником

Не всё, что участник говорит куратору, можно передавать родителям: критику
родителей, сравнение поддержки родителей и друзей, личные переживания,
секреты, семейные конфликты, негативные оценки других людей, отношение к
людям определённой национальности, личные/романтические темы,
информацию, сказанную в доверительном формате, непроработанные внутренние
сомнения.

❌ «Еву перед соревнованиями больше поддерживают друзья, чем мама.» — может
нарушить доверие участника, спровоцировать конфликт, исказить смысл
разговора, создать ощущение оценки родителя. Если наблюдение важно для
работы — остаётся внутри команды, обсуждается отдельно и бережно.

### 8. Не придумывать выводы о личности

Нельзя превращать одну реплику в устойчивую характеристику («Соня
методично вникает в детали», «Илья продемонстрировал самостоятельное
мышление», «Кирилл хорошо ориентируется в инструментах») — только если
это подтверждается наблюдением в динамике, есть конкретные примеры и
команда готова это профессионально обосновать. Писать лучше через
наблюдаемое действие: «Илья самостоятельно подготовит решение кейса и
аргументирует выбранный подход.»

### 9. Не создавать искусственную похвалу

Не добавлять оценку только для тепла тона. Согласие выполнить задание ещё
не доказывает вовлечённость — оценивать можно после выполненного действия.

### 10. Строго разделять факт, гипотезу и план

Нельзя описывать будущее как уже выполненное.
- Было на встрече: участнику передали кейс → ❌ «Илья разобрал кейс
  Deloitte» → ✅ «Илья получил практический бизнес-кейс для самостоятельной
  работы».
- Было на встрече: обсудили возможный период стажировки → ❌ «Стажировка
  начнётся на следующей неделе и продлится до 14 августа» → ✅ «Уточнили
  условия стажировки, чтобы далее согласовать конкретные даты с
  принимающей стороной».
Точные глаголы: получил, начал, подготовил, завершил, обсудил, уточнил,
планирует, предстоит, согласуем.

### 11. Не писать неподтверждённые даты и договорённости

Нельзя указывать как факт дату начала стажировки, продолжительность
практики, конкретного ментора, формат работы, ежедневный контроль,
знакомство со специалистом, подтверждённые задачи, следующую встречу —
если это ещё не согласовано окончательно.

### 12. Не усиливать формулировки без оснований

Возможное ≠ гарантированное. «Спортивные достижения дадут скидку» →
«можно будет учитывать при формировании профиля». «Готовый кейс для
портфолио» (если есть только сертификат) → «опыт и сертификат можно будет
использовать при формировании портфолио». «Реальный кейс Netflix от
Deloitte» (если происхождение не подтверждено) → «практический бизнес-кейс,
основанный на задании для assessment в Deloitte».

### 13. Не перегружать методическими деталями

Не расшифровывать GROW/SMART/ICF, этапы упражнения, все техники, названия
инструментов, содержание презентаций, теоретические определения. Метод
можно назвать, только если это помогает понять направление работы.

### 14. Писать через результат, а не через процесс разговора

«Поговорили / обсудили / рассказали / затронули / пообщались / объяснили»
допустимы, но после них должен идти результат. «Обсудили стажировку» →
«Уточнили запрос Арсения к стажировке и начали подготовку к знакомству с
принимающей стороной.»

### 15. Показывать действие самого участника

Не «куратор рассказал, объяснил, показал, отправил», а «Соня разобрала
базовую структуру коуч-сессии», «Арсений сформулировал ожидания от
стажировки» — фокус на том, что сделал/попробовал/подготовил/
сформулировал участник.

### 16. Объяснять, зачем выполняется задача

Не просто перечислять действия — показывать их смысл: «Арсений доработает
самопрезентацию, чтобы увереннее представить свой опыт на встрече с
принимающей стороной» — а не просто «готовит самопрезентацию».

### 17. Не делать из организационной задачи результат развития

Выбор билета, проверка отеля, отправка файла, выбор времени встречи,
получение ссылки, пересылка презентации, загрузка сертификата — это может
быть частью дальнейших шагов, но не основной содержательный результат.

### 18. Не увеличивать объём искусственно

Если неделя была только поддерживающей встречей без содержательного
продвижения — не выдумывать результат. Короткое честное касание лучше
длинного текста из бытовых подробностей.

### 19. Правильно называть участников

Использовать имя, принятое в текущей коммуникации с семьёй (общий пример —
не «София», если принято «Соня»/«Софья») — не менять привычную форму без
причины и **не смешивать формы внутри одного отчёта** (если в шапке и
приветствии одно имя, в тексте — то же самое, а не более официальный
вариант). Проверять написание по каждому конкретному участнику:

- **Волова Софья** — «Софья», не «София».

### 20. Как писать о поездках и кемпах

Поездка сама по себе не результат трека. Писать о ней только если она
влияет на график встреч, даёт релевантный опыт, связана с портфолио,
является частью профессиональных проб, требует фиксации результата — и
одной фразой, без маршрута и деталей.

### 21. Как писать о сертификатах и портфолио

Сертификат не становится автоматически сильным кейсом. «Сертификат —
готовый кейс для портфолио» → «Сертификат и полученный опыт можно будет
использовать при дальнейшем формировании портфолио». Если роль участника
в проекте не ясна из расшифровки — не преувеличивать содержательность.

### 22. Как писать о стажировках

Этапы нельзя перескакивать: уточнение интересов → подготовка резюме/
самопрезентации → тренировочное собеседование → знакомство с принимающей
стороной → согласование задач/формата/дат → подтверждение стажировки →
начало практики → рефлексия. Пока подтверждён только текущий этап — не
писать про более поздние как про решённые.

### 23. Тренировочное собеседование ≠ реальное собеседование

Разделять: тренировка с куратором (прошлое, «на встрече провели тренировку
собеседования: участник попробовал ответить на вопросы без подготовки») и
знакомство с принимающей стороной (будущее, отдельным предложением).

### 24. Как писать о практических кейсах

Указывать: что участник получил → какую задачу предстоит решить → какой
навык развивается → что будет после выполнения. Не включать спорные
цифры и неподтверждённые детали задания.

### 25. Как писать о коучинговой практике

Никогда не переносить бытовой юмор про приглашённого участника
(«подопытный», «подопытный кролик», «мышка», «тестовый человек») — только
нейтрально: «приглашённый участник», «тренировочная коуч-сессия», «первая
практическая сессия».

### 26. Как писать дальнейшие шаги

Конкретные, реалистичные, подтверждённые, связанные с текущей работой,
понятные родителю. Не «продолжим работу», а «Соня проведёт первую
тренировочную сессию, после чего вместе разберём её опыт и определим
навыки для дальнейшей отработки». Не писать как решённое то, что ещё не
подтверждено («Арсений приступит к стажировке», если стажировка ещё не
согласована).

### 27. Рекомендуемый язык

Профессиональный, спокойный, взрослый, доброжелательный, содержательный,
уверенный, но не категоричный, без канцелярита, без искусственной
восторженности, без воды. Опорные формулировки: «основной фокус был
направлен на», «продолжили работу над», «перешли к следующему этапу»,
«определили», «сформулировали», «уточнили», «зафиксировали», «подготовили»,
«начали», «завершили», «следующим шагом станет», «после этого вместе
разберём», «это позволит», «задача направлена на развитие», «с учётом
текущего графика», «согласуем после», «можно будет использовать при
дальнейшем формировании».

### 28. Формулировок избегать

«хорошая новость», «отличный знак», «прекрасно справился», «очень активно
участвовал», «по-хозяйски», «подопытный клиент», «реальный кейс» (если не
подтверждено), «готовый кейс» (если не оформлен), «гарантированно»,
«точно», «даст право», «повышает шансы» (если нельзя объективно оценить),
«начинается» (если этап не согласован), «прошли тему», «куратор рассказал»
без результата участника.

### 29. Допустимый объём

2–4 коротких абзаца в основном блоке, 1–2 абзаца в дальнейших шагах, одна
содержательная мысль на абзац. Объём зависит от реального содержания
недели, не от желания выглядеть насыщенно.

### 30. Проверка фактов по расшифровке

Перед написанием выписать отдельно: что уже произошло (провели встречу,
получил кейс, завершил лагерь, получил сертификат, определил запрос); что
только планируется (провести сессию, познакомиться, согласовать даты,
подготовить решение); что пока неизвестно (точные даты, итоговые задачи,
длительность, следующий слот). Неизвестное — не додумывать.

### 31. Чек-лист перед отправкой

- **Фактическая точность**: соответствует расшифровке? запланированное не
  описано как выполненное? нет неподтверждённых дат/договорённостей? нет
  усиленных формулировок? гипотеза не выдана за факт?
- **Ценность для родителя**: узнаёт что-то новое? понятно, что изменилось
  и зачем? есть следующий шаг? нет повторения уже известного?
- **Конфиденциальность**: нет личных признаний, критики родителей,
  семейных секретов, нарушения доверия к куратору, информации из личного
  контекста?
- **Стиль**: нет бытового пересказа, конспекта занятия, искусственной
  похвалы, лишних деталей; есть движение; видны действия самого участника;
  использовано привычное имя?
- **Дальнейшие шаги**: конкретны? реально согласованы? не обещают
  неизвестное? связаны с текущим результатом?

### 32. Алгоритм написания

1. Прочитать расшифровку/саммари, выписать все факты.
2. Удалить бытовые истории, личные признания, шутки, известное родителям,
   методические подробности, организационные мелочи.
3. Оставить максимум 2–4 значимых результата.
4. Для каждого результата определить: что сделал участник → что это
   развивает → зачем это нужно → что будет дальше.
5. Проверить, не перепутаны ли прошлое / настоящее / план / предположение.
6. Собрать касание по структуре: результат недели → значение → следующий
   этап.
7. Проверить текст по чек-листу (п.31).

### Образец полного отчёта (эталон стиля, одобрен пользователем)

```
Александр, здравствуйте!

➡️ Отчёт по треку Ильи за период 17.07–24.07

🔸 Синхронизация с куратором

На этой неделе провели с Ильёй индивидуальную синхронизацию. Поскольку
после поездки он ещё восстанавливался, встречу сделали более короткой, но
уже определили следующий практический фокус работы.

Илья получил новый бизнес-кейс, основанный на реальном задании для
assessment в Deloitte. В рамках кейса ему предстоит разработать стратегию
возвращения молодой аудитории стримингового сервиса с учётом заданного
бюджета и ограниченного срока реализации.

Задача направлена на развитие аналитического и стратегического мышления:
Илье важно будет не только предложить идеи, но и обосновать их, определить
приоритеты и собрать решение в понятную структуру.

Также договорились после восстановления отдельно синхронизироваться по его
актуальным интересам и запросам, чтобы определить следующие менторские
знакомства и направления обучения.

Отдельно на семейной встрече сверили основные организационные вопросы
предстоящей поездки в США и ближайшие задачи по подготовке.

🔸 Дальнейшие шаги

На следующем этапе Илья самостоятельно подготовит решение бизнес-кейса.
После этого вместе разберём его подход, сравним с примером решения и
обсудим обратную связь, полученную по исходному кейсу.

Параллельно определим приоритетные темы для следующих менторских встреч,
чтобы они были связаны с текущими интересами и задачами Ильи.
```

Почему это хорошо: нет пересказа бытового разговора (болезнь — одной
фразой, только чтобы объяснить формат встречи), нет лишней логистики
поездки (семейная встреча — одна строка, без деталей класса перелёта/
отеля, которые родитель и так знает), нет преждевременной похвалы (не
«проявил вовлечённость», а нейтрально «получил кейс», «предстоит
разработать»), чётко разделены факт (кейс получен) и будущее (кейс будет
решён, потом разобран вместе).

### 33. Короткая памятка (сжатая версия всего вышеперечисленного)

Используй только информацию из расшифровки/саммари встречи и известного
контекста участника. Ничего не додумывай. Касание — не пересказ встречи и
не конспект занятия, а короткий ответ на: что произошло → что сделал/
сформировал участник → какой навык/результат развивается → какой
следующий шаг согласован.

Обязательно:
- отделяй уже выполненное от запланированного;
- не указывай неподтверждённые даты;
- не превращай гипотезы в факты;
- не обещай несогласованный формат работы;
- не включай информацию, которую родители уже знают (включая оценки/
  баллы, которые они и так получили);
- не пересказывай встречу, на которой родители присутствовали;
- не включай бытовые детали, шутки и случайные темы;
- не передавай личные признания участника и то, что нарушает
  доверительность;
- не придумывай оценки личности и искусственную похвалу;
- не перегружай текст названиями методик и теорией;
- показывай действия участника, а не только куратора;
- объясняй, зачем нужен текущий этап;
- используй привычную для семьи форму имени участника;
- пиши от лица «мы» (команда/куратор), не в третьем лице о себе.

Финальная проверка перед отправкой: все факты подтверждены? нет известной
родителям информации? нет бытового пересказа? нет нарушения
конфиденциальности? будущее не описано как уже состоявшееся? нет
неподтверждённых дат и обещаний? (полный чек-лист — см. п.31)
